One question, end to end

“What's the largest instance running in account 392918273645?”

  1. The agent sends Claude the question, the system prompt and the four tool definitions it got from the MCP server with tools/list.
  2. Claude answers with a tool_use block: find_instances(account_id, state="running", sort_by="vcpus", descending=true). The tool description told it how to rank.
  3. The agent calls the MCP server with a token whose audience is ec2-mcp. The server checks the signature against the API's JWKS.
  4. The MCP server never forwards that token. It exchanges it for a short-lived ec2-api token for the same user, with itself recorded as the actor.
  5. It calls GET /v1/ec2/instances. The API checks the user's scopes and answers from the in-memory latest snapshot in a few milliseconds.
  6. Only history questions (a terminated instance, a 30-day timeline) read Iceberg: DuckDB prunes to the needed day partitions in S3.

The tool result goes back to Claude, which may call another tool (for example, to break a vCPU tie by memory) or answer with the snapshot time.
